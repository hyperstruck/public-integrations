# RunStatusResponse

## Properties
Name | Type | Description | Notes
------------ | ------------- | ------------- | -------------
**claim_count** | **object** | Claims this run&#x27;s records wrote or corroborated, each counted once. Null until the job finishes, which is not zero. | [optional]
**corpus_items_lost** | **object** | Evidence items you sent that nothing managed to read, counted once each. Non-zero means resending is worthwhile; the claims from every item that was read are still stored. Together with corpus_items_with_claims it can never exceed the number of items you sent, and an item can be in neither, which means it was read and stated no claim. | [optional]
**corpus_items_with_claims** | **object** | Evidence items you sent that produced at least one claim, counted once each. Null until the job finishes, and 0 on a job that carried no corpus. Read beside corpus_items_lost: a corpus that held few facts and one the extraction never read are different answers, and only one is worth resending. | [optional]
**declared_subject_items** | **object** | Items you sent that declared a &#x60;subject&#x60;. Every claim from such an item is filed under that subject rather than under an entity read from its prose, so this is the count that explains a shelf holding one entity per document. Null on a non-corpus run and on a run that finished before this was measured; zero is a measurement and means extraction chose every entity itself. | [optional]
**documents** | **object** | On a run whose items were stored as documents, one entry per evidence item in request order: the document it became (&#x60;doc_id&#x60;, &#x60;version&#x60;) and its &#x60;outcome&#x60;: &#x60;queued&#x60; while its ingest is pending, then &#x60;stored&#x60; (a new document), &#x60;new_version&#x60; (changed text under an existing document), &#x60;unchanged&#x60; (identical text already stored, so nothing was read again), &#x60;refused&#x60; with a &#x60;reason&#x60;, or &#x60;failed&#x60;. Readable while the run is in progress. Null on a run whose items were not stored as documents. | [optional]
**finished_at** | **object** |  | [optional]
**is_read_complete** | **object** | Whether every item was read to the end with no pass failing. This is what separates a zero worth accepting from a zero worth resending, and zero_reason is derived from it: contrast_not_found when true, nothing_extracted when false. | [optional]
**items** | **object** | What the reader did with each item you sent, one entry each. Null until the job finishes, and null on a run finished under a Core older than the reader; empty on a run that carried no corpus. This is the answer corpus_items_with_claims and corpus_items_lost could only approximate: which of your documents produced which learning, and which the extraction never reached. | [optional]
**learning_count** | **object** | Learnings stored. Null until the job finishes, which is not zero. | [optional]
**learnings_dropped_over_cap** | **object** | Learnings that passed every quality gate and were withheld because the max_learnings you asked for was already met. This is not a quality judgement: those are counted by the critic. Non-zero means this corpus held more than you asked for, and raising max_learnings on the next call would return them. | [optional]
**obligation_outcomes** | **object** | What became of each typed obligation this run&#x27;s evidence carried, one entry per obligation submitted. Null distinguishes two different things: a run that carried no typed obligations, and one that has not finished yet (typed obligations are written by the worker itself, never at accept, so a mid-run poll also reads null here). | [optional]
**obligations_written** | **object** | Owed claims stated in the prose this run ingested: what someone is to do. Null on a run that finished before this was measured, or under a deployment pinned to a Core that never counted it; zero is a measurement and means the lane ran and found nothing. Counts the corpus lane only: the agent&#x27;s own answer is reported separately as own_output_obligations_written, because one number moved by two lanes with different triggers cannot be attributed to either. | [optional]
**own_output_obligations_written** | **object** | Obligations this run harvested from the answer the agent itself composed, written to the shelf held for review. Null means not measured, zero means the lane ran and found no commitment; the two readings are what makes &#x27;the lane is enabled and the shelf is empty&#x27; answerable at all. Read the rows themselves with GET /agents/{agent_id}/claims?kind&#x3D;obligation&amp;state&#x3D;open. | [optional]
**pairs_folded** | **object** | Contrast pairs the reader found and could not give a pass of their own. They were still read inside the compacted remainder, so this sizes how much sharper the read could have been, not what was lost. | [optional]

**steps_failed_unexplained** | **object** | Failed steps that carried a status and nothing saying why they failed. No learning is written from one, because a guess at the cause is worse than no learning. Non-zero means your host is sending failures without their reason: put it in the step&#x27;s error field. Null until the job finishes, and on a run whose failed steps nobody counted (learning extraction was held or did not run), which is not the same as zero. | [optional]
**steps_stubbed** | **object** | Items whose full text the budget compacted to a one-line summary. Not a loss, and non-zero is the ordinary shape of a large job: every item still has its line in the run sketch that each pass reads. | [optional]
**steps_unread** | **object** | Items nothing managed to read at all. Expected 0, because the reader keeps a summary line for every item rather than dropping a tail. Non-zero is worth acting on. | [optional]
